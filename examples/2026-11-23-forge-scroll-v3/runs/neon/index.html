02 / BEFORE TURN 1 capture → rate → plan → preflight

Stop bad runs before an agent ever opens a file.

Unattended agents rarely fail because the model is weak. They fail for boring operational reasons: the task was vague, two lanes edited the same file, or the verification command was broken from the start. Forge turns each of those failure modes into a deterministic check before turn 1.

1. Capture & Rate PROJECT/1-INBOX/ · PRS

Write it down once, then score it honestly

GH-148 starts as a GitHub issue, becomes a capture doc in PROJECT/1-INBOX/ with a why, phases, and a verification contract, and lands as a parked row in the Product Release System (PRS) ledger scored on pri, sev, appeal, and effort. Forge does not invent your spec—you and your LLM author it, and Forge checks whether it is runnable.

2. Wave Planner Exact write-set intersection

Prove two lanes cannot collide

Before dispatching, the wave planner checks exact write-set intersections, zone caps, and dependencies. GH-148 touches billing/webhooks.ts; a second queued task touches billing/invoices.ts. Zero overlap means they can share a wave. A third task touching billing/webhooks.ts is held for the next wave automatically.

3. Preflight Verdict Schema-stamped JSON

The gate must start before the builder starts

Preflight runs freshness probes, checks whether the fix already landed, and verifies the test gate can actually execute before turn 1. If a repo has known pre-existing test failures, --pre-advance-baseline <rc> lets the gate tolerate that exit code while still halting on any new regression.

Machine-readable boundaries

State crossing a subsystem boundary travels as a schema-stamped JSON artifact with explicit nulls—never scraped out of terminal logs or prose.

Deterministic before advisory

Anything expressible as a regex, schema, or file check runs deterministically and may block. LLM review may warn, rank, or propose—it may never block.

Containment enforced by the harness, not by polite prompting.

04 / PROOF & MEMORY gate → land → record

"Done" means the suite is green and the doc contract holds.

When the builder and reviewer converge on GH-148, nothing is trusted on their say-so. A resource-capped verification gate runs, PDDA checks that disk docs match reality, and the PRS ledger writes a git-mergeable receipt so you can audit—or resume—tomorrow.

Gate · Resource-Contained Proof CPU / Wall / RSS Caps

Runaway test suites get killed cleanly, not misfiled as bugs

Every phase boundary runs its verification gate under wall-clock, CPU, and RSS containment. If a test leaks memory or loops forever, Forge kills it with exit code 108 and escalates distinctly so a resource runaway is never triaged as a product defect.

PDDA · Docs as Runtime State PROJECT/**

Not paperwork—serialized machine state

Forge's built-in doc governance (PDDA, in utils/pdda/) validates frontmatter, status tables, and ledger coverage. Why enforce doc checks with teeth? Because unattended agent work must be stoppable, resumable, and handable to a fresh session from PROJECT/** alone. Drift between code and docs is a runtime defect, not untidiness.

Recovery · Honest Post-Crash Triage marathon-recover.sh

If a run dies mid-flight, inspect without guessing

Running bash relay-automation/marathon-recover.sh /path/to/repo produces a read-only report over phase records, the tick log, and reachable commits. Any phase that committed without an approval event is flagged as an UNGATED COMMIT—treat it as unverified. A stale .git/relay-driver.lock self-heals on the next start; a LIVE lock warns you another driver is still active.

05 / CLEAR-EYED ADOPTION scope · hardware · 60-second proof

Know what you are adopting—and prove the kernel in 60 seconds.

XYZ Forge is beta, single-operator software moving fast. Most commits are agent-authored, and local-first is a deliberate design constraint, not a roadmap gap. Decide with full facts before you wire it into a repository.

What Forge Is

  • Local-first ops for a small human team directing a larger number of AI coding agents across their own repos.
  • Gradual adoption: Consult and Relay need zero governance setup; add PDDA and vendored .xyz/ only when you want Swarm/Marathon.
  • ~50 cadence-grouped skills (1-hourly/ through 4-occasional/) plus a Python runtime by default (with frozen Bash fallbacks).
  • AGPL-3.0-only with a commercial license option (LICENSE-COMMERCIAL.md).

What Forge Deliberately Is Not

  • Not enterprise ALM: No multi-user identity, RBAC, SSO, cross-team capacity planning, or regulatory traceability matrix. If you need Polarion or Azure DevOps, use them.
  • Not a spec generator: It assumes specified work. Pair it with GitHub Spec Kit or Task Master if you want structured prompt-to-PRD generation; their output can land in PROJECT/1-INBOX/.
  • Not hands-off magic: No release tags yet, Python static analysis is currently absent, and host-aware wave sizing stays the operator's job.

Two operational gotchas before your first run

Most Common False Alarm
Run validate.sh un-sandboxed. Under Claude Code's default Bash sandbox, mktemp -d scratch dirs are blocked: the suite prints nothing for minutes, then fails. Turn off the sandbox (/sandbox) before assuming it is broken.
Mandatory Hook Per Clone
The pre-push hook lives in .git/hooks/ and does not travel with a clone. Run bash githooks/install.sh once per clone (check with --check) so fresh clones are never ungated.
Gate Toolchain
Full gates require Python ≥ 3.10 (PyYAML, pytest, requests, pinned mypy via requirements-dev.txt). No accounts or API keys required to run ./validate.sh.
